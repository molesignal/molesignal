## Why

`implement-backend-mvp` 装配了主链路并跑通端到端最小路径，但 `ingester / querier / compactor / alert_manager` 四个 role 都是 stub —— 写入仍是 `MemoryIngestSink`（进程一挂全丢、不走 WAL→buffer→parquet）、查询不能跨节点扇出、小文件不会被合并、告警规则不会被周期评估。同时 OpenObserve 的核心定位 —— **基于 Parquet+S3 的列存 + 分区/索引/缓存使搜索空间至多减少 99% + SQL/PromQL 双引擎 + 原生多租户 + 无状态架构** —— 还停留在文档里：PromQL 是 `UnimplementedPromqlEngine`，Tantivy 是空 struct，文件元数据每次查询都重读 DB，并没有任何缓存层；多租户隔离只在 query handler 的 `req.org_id = ctx.org_id` 一处兜底，跨 capability 还没系统化。本 change 把这些一次性补齐，让 molesignal 真正具备 OpenObserve 同等量级的能力。

## What Changes

- **Ingester role 真实化**：用 `SegmentWal` + 内存 Arrow `RecordBatchBuilder` per `(org, stream_type, stream)` 替换 `MemoryIngestSink`；按 `ingester.buffer_max_mb` / `flush_interval_secs` 触发 flush → `ParquetWriter::flush` → `ParquetFileMetaRepository::insert` → 截断对应 WAL 段；启动重放未 flush 的段；ingester gRPC server 上线供 router 转发。
- **Compactor role 真实化**：周期扫每 `(org, stream, stream_type, date)` 下 `size_bytes < compactor.target_mb` 的 `ParquetFileMeta`，按时间相邻合并、生成新 parquet、`ParquetFileMetaRepository::replace` 事务交换；retention 扫描按 `StreamDefinition.retention.days` 把过期 ParquetFileMeta 标 `deleted=true` 并删 object。
- **Querier role 真实化（Arrow Flight 分布式）**：所有 querier 通过 cluster registry 互相发现；coordinator 把 `ParquetFileMeta` 候选集按一致性哈希切片下发 `do_get` `Ticket`；执行节点用 `ParquetExec` + projection/predicate pushdown 出 `RecordBatch` 流；coordinator 端 `MergeExec` 汇总后下发给 DataFusion 完成 final aggregation。单 querier 时直接本地执行。
- **PromQL 引擎**：新增 `PromQLEngine`（基于 `promql-parser` + 自实现 evaluator over Arrow），覆盖 instant / range query、`rate / increase / sum / avg / histogram_quantile`，对接 metrics stream 的 `_timestamp + labels(json) + value(f64)` 列布局。
- **Tantivy 倒排索引**：写入路径在 `ParquetWriter::flush` 同时构建 `indexed=true` 字段的 Tantivy 索引，序列化为 `{object_key}.tantivy.tar.zst` 并 put 到 object store；查询路径在 `ParquetExec` 之前用 `MATCH(field, term)` 谓词查倒排，命中 0 文档则把该 `ParquetFileMeta` 从候选集踢掉。
- **智能缓存层（新增 `caching` capability）**：进程内三级 LRU —— `parquet_file_meta`（org/stream/time-bucket → Vec<ParquetFileMeta>，1 min TTL）、`parquet_metadata`（object_key → Arc<ParquetMetaData>，弱引用）、`query_result`（hash(stmt, org, time_range) → QueryResult，TTL 60s，仅对纯只读 SQL 启用）。每级带 hit/miss/evict metric。
- **Alert manager role 真实化**：`RuleEvaluator::tick` 每 `eval_interval_secs` 对启用规则执行查询 → 比较阈值 → `for_periods` 计数 → 开/关 Incident；`EscalationDispatcher::tick` 接 10.3 已落地的派发函数，按 `current_step` + `ack_timeout_secs` 推进或循环；首个 step 立刻发，超时只升级一次/tick；通通经 `DeliveryRepository::record` 落盘。
- **Cluster registry**：`NodeService::Heartbeat` server 端落 `cluster_nodes` 表（node_id、role、advertise_addr、last_seen_ts），15s 未续约自动剔；router / coordinator querier 都从这张表选下游；首个心跳出现时所有 role 在 `wire::build_state` 末尾启动一个 5s 心跳任务。
- **Router role 真实化**：基于 cluster registry 选 ingester（按 `(org, stream)` 一致性哈希）/ querier（轮询）；对 `/api/v1/ingest/*` 与 `/api/v1/query` 路径做 token-bucket 限流（`(org_id, route)` 维度）；返回 `429 Too Many Requests` + `Retry-After` 头。
- **`/metrics` 端点 + OTLP exporter**：HTTP router 挂上 `/metrics`（Prometheus text format，免鉴权）；`shared::telemetry::init_full` 在 `otlp_endpoint != ""` 时真正装配 `opentelemetry-otlp` exporter 与 `tracing-opentelemetry` layer。
- **gRPC server 完整装配**：`api/src/grpc/mod.rs` 用 `tonic::transport::Server::add_service` 同时挂 `cluster.NodeService` + `ingest.IngestService` + `arrow_flight.FlightService` 三个 server；bind `grpc.bind:port`，与 HTTP 同进程 `tokio::try_join!`。
- **多租户系统化加固**：所有 service / repository 方法签名第一参数统一为 `org_id: Id`；SQL 查询的 `FROM <stream>` 路径在 planner 阶段重写为 `org_id-scoped` 物理引用；alerting / dashboard / schedule / channel 全部加上 `WHERE org_id = $1` 检查；新增 `tests/it_multitenant.rs` 端到端验证跨 org 不可见。
- **无状态保证**：ingester 关进程不会丢未 ack 的数据（WAL 落盘 + 启动重放 + buffer 持续追加 WAL 直到 flush 成功）；querier/compactor/alert_manager 进程重启完全无状态（所有状态在 meta_store + object_store）；router 端无 sticky session；`ingester.wal.dir` 是节点唯一本地状态，丢失等价于丢失尚未 flush 的窗口数据（≤ flush_interval）。
- **Identity CRUD**：补齐 `/api/v1/users`、`/api/v1/orgs`、`/api/v1/orgs/:id/members`、`/api/v1/teams` 全部 CRUD，包括首个用户自动建 default org + Owner membership 的路径。
- **HTTP API 全量上线**：archived MVP 里所有以 `400 "TODO add payload"` 兜底的 handler 全部接通 —— Alert（rules / channels / escalation policies）、Schedule（schedules / rotations / overrides / on-call）、Dashboard（含 Folder + Grafana 双向）、Stream（CRUD + 手动 schema 编辑 + retention 调整）三大块的 create/update 路径补齐请求与响应负载结构，统一放在每个 handler 文件内（命名 `*_request.rs / *_response.rs`，**不出现 `dto` 字眼**）；同时新增 Saved View（保存的查询）、Function（VRL/JS 转换函数）、Pipeline（ingest-time 多步 function 链）三类用户态资源的完整 HTTP API。每个写路径 handler 都走同一套 `validate → service → IntoResponse` 流程；list 路径统一支持 `?page=&page_size=&filter=` 分页与简单过滤。
- **多协议 ingest 接入**：在已有 `POST /api/v1/ingest/{logs,metrics,traces}/:stream` JSON 路径之外新增 OO 完整入口矩阵 —— **OTLP gRPC**（`opentelemetry.proto.collector.{logs,metrics,traces}.v1`）+ **OTLP HTTP**（`POST /api/v1/{logs,metrics,traces}` protobuf/JSON）+ **Prometheus remote_write**（`POST /api/v1/prometheus/api/v1/write` snappy+protobuf）+ **Elasticsearch 兼容**（`POST /api/v1/_bulk`、`/_json`、`/_multi`）+ **Loki push**（`POST /api/v1/loki/api/v1/push` 含 promtail 标签集）+ **Syslog UDP/TCP listener**（RFC3164/RFC5424，绑 `[syslog].udp_bind / tcp_bind`）+ **Kinesis Firehose**（`POST /api/v1/_kinesis_firehose` Base64 解码 → 行拆分）。所有协议落到同一 `IngestService::ingest` 路径前先做协议→`IngestBatch` 转换。
- **Real-time alerts**：除现有 scheduled alerts 外新增 `AlertRule.kind = RealTime`；rule 在 alert_manager 上线时被分发到所有 ingester，ingester 在 `IngestService::ingest` 写 WAL 后同步用 `RealTimeMatcher`（VRL-style 谓词或 SQL WHERE 片段）对每条事件做即时匹配，命中后立刻 emit `IncidentEvent` 经 gRPC 上报给 alert_manager，由现有 dispatcher 派发；事件 → 通知端到端目标 < 1s。
- **API tokens**：新增 `/api/v1/auth/tokens` CRUD，签发不可逆 prefix-visible token（首半段 `ms_` + 16 字符 random ID，后半段 32 字符 secret，仅创建时返一次），DB 存 argon2(secret)；middleware 同时支持 `Authorization: Bearer <jwt>` 与 `Authorization: Bearer ms_...` 两种；token 可绑 `org_id / role / expires_at / last_used_at`。
- **Audit log**：新增 `audit_events { id, org_id, actor_kind, actor_id, action, target_kind, target_id, ip, user_agent, payload(json), ts }` 表 + handler 中间件，覆盖所有 mutating handler（create/update/delete + login + token issue/revoke）；`GET /api/v1/audit?from=&to=&actor=&action=` 提供查询，仅 `Admin+` 可见。
- **Enrichment tables**：新增 stream_type `enrichment`，行内容为静态 KV（`key, value_json`），ingester 启动时把 `enrichment` 表 mmap 到进程内 `HashMap<String, serde_json::Value>`；新增 VRL 内置函数 `lookup(table, key)` 让 pipeline function 在转换时查表。
- **Search around + Streaming search**：新增 `POST /api/v1/query/search_around { event_pointer, before, after }` 返回 hit 前后各 N 条事件；查询响应支持 `Accept: application/x-ndjson` 走 axum SSE / chunked transfer，按 `RecordBatch` 流式返；客户端可在结果还在执行时拿到首批行。
- **Service graph**：traces ingester flush 时同步喂 `crates/infra/src/traces/service_graph.rs` 内存聚合器，按 `(client_service, server_service, time_bucket_min)` 累计 `request_count / error_count / duration_quantiles`；每 minute 滚动落到 `service_graph_edges` 表；`GET /api/v1/traces/service_graph?from=&to=` 返聚合图。
- **Disk cache**：在 `caching` 上扩 `parquet_disk_cache`：当 `caching.disk_cache.enabled = true` 时 `parquet_reader` 先看 `<disk_cache.dir>/<sha256(object_key)>` 是否存在且校验和一致 → 命中走本地磁盘读，未命中走对象存储 + 后台异步落盘；按 `max_size_gb` LRU 驱逐。
- **Org-level quotas**：新增 `quotas { org_id PK, max_ingest_qps, max_query_qps, max_storage_bytes, max_streams }`；ingest path 在 `IngestService::ingest` 入口走 `governor` 桶（per org）；query 入口同；compactor 每小时算一次 `(org → sum(parquet_file_meta.size_bytes))`，超 `max_storage_bytes` 时阻塞新 ingest（返 `413 Payload Too Large`）并发 audit + alert。
- **Scheduled pipelines**：除 ingester 内 inline pipeline 外，新增 `ScheduledPipeline { id, org_id, name, source_stream, target_stream, function_steps, cron, last_run_at, lookback_secs }`；alert_manager（或新 scheduler role）按 cron 触发 `ScheduledPipelineRunner`：扫源 stream 时间窗 → 跑 function 链 → 写目标 stream（走标准 `IngestService::ingest`）；用于历史回灌、降采样、聚合到 summary stream。
- **Alert templates**：channel + escalation step 引入 `body_template` 字段，handler 用极简 mustache（`{{var}}`）替换，可用变量 `{ rule.name, incident.fingerprint, incident.labels.*, value, threshold, evaluated_at, org.name }`；模板渲染失败保留原文 + 加 warn metric。
- **Anomaly detection（MVP）**：新增 `AlertRule.kind = Anomaly`；运行时按 `lookback_days`（默认 7）算同环比基线：每个评估时间点的"应该值"= 过去 N 天同时刻同 weekday 的中位数 + 1.4826·MAD（鲁棒 σ）；触发条件改为 `|current - baseline| > k * mad`（默认 k=3）。trait `AnomalyDetector` 留接口，初版仅 `MadDetector`；EWMA / Prophet / Isolation Forest 占位 stub 返 `unimplemented`。
- **LLM telemetry（MVP）**：新增 stream_type `llm_traces`（schema 含 `model, provider, prompt_tokens, completion_tokens, total_tokens, cost_usd, latency_ms, prompt_redacted, completion_redacted, status, error`），OTLP traces 入口在 span attribute 含 `gen_ai.*` 时自动 fan-out 写一份到 `llm_traces`；新增 `/api/v1/llm/{stats,top_models,top_users}` 派生查询；prompt/completion 默认走 `redact_pii` VRL 函数（pipeline 自动注入）。
- **RUM（MVP）**：新增 stream_types `rum_sessions / rum_actions / rum_errors / rum_replay_events`；HTTP receiver `POST /api/v1/rum/{sessions,actions,errors,replay}` 接受 Datadog RUM 兼容 JSON（最常见的开源 RUM 入口契约）；session_id 关联到 traces；replay event 走 object_store（每条 session 一个 `rum/<session_id>.replay.ndjson.zst`）；不实装前端 SDK 与 player，只做接收 + 存储 + 查询接口。
- **SSO/SAML（MVP）**：新增 `[auth.sso] enabled=false, provider="oidc"|"saml", oidc { issuer, client_id, client_secret, redirect_uri, scopes[] }, saml { sp_entity_id, idp_metadata_url, cert_pem_file }`；handler `GET /api/v1/auth/sso/login` 重定向 IdP、`GET/POST /api/v1/auth/sso/callback` 接 IdP 回调并发本地 JWT；用户首次登录自动 `provision_user(email, org)`，role 默认 `Viewer`，可经 `[auth.sso].role_mapping[]` 按 IdP group claim 提升；不实装 SCIM/JIT 复杂细节。
- **Federated search（MVP）**：新增 `RemoteCluster { id, name, advertise_addr, token_secret_ref, tls_verify, enabled }` + `/api/v1/clusters` CRUD；查询带 `?clusters=local,sf,nyc` 时 coordinator 对每个 remote cluster 起独立 `arrow_flight::do_get`（携 service-account token），结果与本集群结果 union 后再跑 final aggregation；失败 cluster 默认 partial-degraded（响应 `degraded_clusters: [...]`）。
- **Cipher keys（MVP）**：新增 `cipher_keys { id, org_id, alg, version, key_material_enc, created_at, rotated_at }` + `/api/v1/cipher_keys` CRUD（仅 Owner）；key material 用 master key 解密（master key 来自环境变量 `MS_MASTER_KEY`，无则启动失败）；新增 VRL 函数 `encrypt(value, key_id)` / `decrypt(value, key_id)` 给 pipeline 使用；非对称 KMS 不接，至少把字段级加密 + key rotation 跑通。
- **License management（MVP）**：新增 `[license] file = "/etc/molesignal/license.json"`；启动时解析签名 license（Ed25519 by Anthropic root key — 此处用项目自管 root key，由 license-issuer CLI 出 demo license）；含 `max_ingest_bytes_per_day, max_users, expires_at, features[]`；超限 → 阻断写并提示续期；缺 license file 默认 community 模式（无上限，不含 `enterprise` features）。
- **Cloud connectors（MVP）**：新增独立 `connector` role + `connectors { id, org_id, name, kind, config_json, enabled, last_run_at }`；初版实装 4 个 kind —— `aws_cloudwatch_logs`（每 30s pull）、`aws_kinesis_firehose`（已在 ingest-protocols 内）、`cloudflare_logpush`（HTTP receiver `/api/v1/_cloudflare`）、`heroku_drain`（HTTP receiver `/api/v1/_heroku`）；各 connector 通过统一 `Connector trait` 实现 `pull` 或 `accept_push`，结果走标准 `IngestService::ingest` 路径。
- **对象存储生产化接入**：在 archived MVP 多 backend 之上加 **multipart upload（parquet > `object_store.multipart_threshold_mb` 默认 32 MiB 自动切片并发上传）**、**range-based 分块下载与并发拼接**、**指数退避 + jitter 重试（针对 transient `5xx / Throttling / SlowDown / Timeout`，最多 `retry.max_attempts` 次）**、**per-operation timeout** 与 **并发上限 semaphore**；保留静态 AK/SK 凭证路径（不引入云原生凭证链），但凭据来源支持 **配置文件**、**`MS_OBJECT_STORE_SECRET_KEY` 环境变量**、**`credentials_file` 路径**三种；新增跨 backend 统一指标族 `object_store_{operations,bytes,errors}_total{backend,op}` 与 `object_store_op_duration_seconds`；启动时执行 **bucket reachability ping**（put → get → delete 一个 `health/<uuid>` 小对象），失败则 `wire::build_state` 直接返错；`/api/v1/healthz` 周期复查 object store 写读延迟，超阈值标 degraded。

非目标：bloom filter 持久化（仅依赖 Tantivy + min/max）、跨 region 多活、PromQL 全函数集合（仅覆盖列出的 8 个）、`web/` 前端改动、前端 RUM SDK 与 session player（仅做 receiver + 存储 + 查询接口）、prophet/iforest 等高级异常检测算法（仅 MAD 基线）、SCIM/JIT 复杂 user provisioning、KMS-as-a-service 集成（仅本地 master key + 字段级加密）、graceful shutdown（独立 change）。

## Capabilities

### New Capabilities

- `caching`：跨 capability 共享的进程内多级缓存（parquet_file_meta / parquet_metadata / query_result）+ 本地磁盘 parquet cache，含 LRU + TTL + 指标。
- `pipeline`：ingest-time 转换函数（VRL/JS）+ 多步 Pipeline 编排（real-time + scheduled）+ Enrichment lookup + Saved View（保存的查询/查询历史），含 HTTP CRUD 与执行时与 ingester 的接入点。
- `ingest-protocols`：OTLP gRPC/HTTP + Prometheus remote_write + Elasticsearch `_bulk`/`_json`/`_multi` + Loki push + Syslog UDP/TCP + Kinesis Firehose 共 7 类协议的 receiver，统一收敛到 `IngestService::ingest`。
- `audit`：`audit_events` 表 + handler 中间件 + 查询接口；覆盖所有 mutating 操作 + 登录 + token 操作。
- `quotas`：org-level ingest QPS / query QPS / storage bytes / stream count 配额，超限拒绝并审计。
- `traces`：traces 写入派生 `service_graph_edges` 聚合 + `/api/v1/traces/service_graph` 查询接口。
- `anomaly-detection`：`AlertRule.kind = Anomaly` + `MadDetector`（MAD 基线 + 3σ）+ `AnomalyDetector` trait（其它算法占位）。
- `llm-telemetry`：`llm_traces` 派生 stream + OTLP `gen_ai.*` 自动 fan-out + 派生查询接口 + 默认 PII redact。
- `rum`：`rum_sessions/actions/errors/replay_events` 4 个派生 stream + Datadog-RUM 兼容 receiver + replay event object_store 路径。
- `sso`：OIDC + SAML 2.0 minimum-viable IdP 集成 + auto-provision + role 映射。
- `federated-search`：`RemoteCluster` 注册表 + 跨集群 Arrow Flight 扇出 + 部分降级返回。
- `cipher-keys`：org-scoped 字段级加密 key 管理 + VRL `encrypt/decrypt` 函数 + master-key envelope。
- `license`：Ed25519 签名 license 文件解析 + max_ingest/users/expires 阻断 + feature gating。
- `cloud-connectors`：`Connector` trait + 4 个 initial impl（CloudWatch pull / Kinesis Firehose push / Cloudflare logpush / Heroku drain），独立 `connector` role 调度。

### Modified Capabilities

- `ingestion`：WAL + buffer + periodic flush 路径从 stub 转为真实；ingester gRPC server 上线；新增 Stream 管理 HTTP CRUD（含 enrichment 类型）；schema/retention 子路由独立。
- `storage`：compactor 周期合并 + retention 真实化；Tantivy 索引随 parquet 同写同存同查；object 删除链路对齐 ParquetFileMeta 事务；object store 接入 multipart / range / retry / metrics / health。
- `query`：PromQL 真实引擎；Arrow Flight 分布式扇出；Tantivy 谓词裁剪；query result cache；planner 强制 org_id scope；新增 Saved View / Search Around / Streaming Search HTTP API。
- `alerting`：RuleEvaluator + EscalationDispatcher 在 alert_manager role 内周期 tick；Delivery 真实落库；Alert Rule / Channel / Escalation Policy 完整 HTTP CRUD（命名走 `*_request.rs` / `*_response.rs`，不用 dto 字眼）；新增 `kind: Scheduled | RealTime | Anomaly` + Template 系统。
- `cluster`：节点心跳 + 注册表真实化；router 真实代理 + 限流；gRPC server 装配；ingester/querier 间内部 RPC 上线；新增 RemoteCluster 注册（供 federated search 用）。
- `telemetry`：`/metrics` 端点真实；OTLP exporter 装配；HTTP 请求级 span 自动注入。
- `identity`：users/orgs/memberships/teams CRUD 路由真实化；首用户自动建 org + Owner；新增 API tokens CRUD + SSO（OIDC/SAML）登录路径。
- `dashboard`：Folder + Dashboard 完整 CRUD（create / update / delete / list_by_folder / move）；Grafana 导入路径与 native create 并存；新增 `?page=&page_size=` 分页统一约定。

- **APIs**：HTTP `/api/v1/{users,orgs,teams,members,streams,dashboards,folders,alerts/*,schedules/*,saved_views,functions,pipelines}` 全量；`/metrics` 公开；`429` 与 `Retry-After` 出现在限流场景；查询响应新增 `cache_hit: bool` 字段；所有 list 路径统一 `?page=&page_size=&filter=` query string。
- **gRPC**：`cluster.NodeService { Heartbeat, List }`、`ingest.IngestService { Push }`、`arrow_flight.FlightService { do_get, get_flight_info }` 全部上线。
- **依赖**：新增 `promql-parser`、`opentelemetry-otlp` + `opentelemetry_sdk` + `tracing-opentelemetry`（统一锁版本组合）、`opentelemetry-proto`（接收侧 proto 解析）、`prometheus`（exposition + remote_write 解析）、`prost`（remote_write protobuf）、`snap`（snappy 解码）、`moka`（LRU + TTL）、`consistent_hash_ring` 或自实现一致性哈希、`vrl`（VRL 转换函数）、`backon`（指数退避）、`syslog-loose`（Syslog RFC3164/5424 解析）、`openidconnect`（OIDC）、`samael` 或自实现（SAML 2.0 SP）、`ed25519-dalek`（license 验签）、`aes-gcm`（字段级加密）、`reqwest`（cloud connector pull）。JS function 走 `boa_engine` 沙箱（可选 feature `js`，默认关闭）。
- **数据库**：新增 `cluster_nodes`、`alert_rule_eval_state`、`saved_views`、`functions`、`pipelines`、`scheduled_pipelines`、`api_tokens`、`audit_events`、`quotas`、`service_graph_edges`、`remote_clusters`、`cipher_keys`、`connectors`、`enrichment_kv`、`sso_sessions` 共 15 张表的迁移；`alert_rules` 加 `kind`/`anomaly_params_json`/`body_template` 列；`channels` 加 `body_template`；`organizations` 加 `quota_id` FK。
- **配置**：`[ingester]` 新增 `buffer_max_mb / flush_interval_secs`；`[compactor]` 新增 `interval_secs / target_mb`；`[alert_manager]` 已有 `eval_interval_secs / dispatch_interval_secs`；`[cluster]` 加 `advertise_addr`；`[caching]` 新段（三级各自的 `capacity / ttl_secs`）；`[object_store]` 加 `multipart_threshold_mb / multipart_part_size_mb / max_concurrency / op_timeout_secs / retry.{max_attempts, base_backoff_ms, max_backoff_ms, jitter_ratio}`；`[pipeline]` 段控制 function 执行 `cpu_time_ms_limit / memory_mb_limit / wall_time_ms_limit`。
- **部署**：docker compose / k8s manifest 增加 `cluster.advertise_addr` 注入；k8s 各 role 的 Service 暴露 gRPC 端口；ingester StatefulSet 已有 PVC（WAL 盘），无需新增。
- **测试**：新增端到端覆盖 ≥ 25 套，覆盖三大流（ingest 协议矩阵 / 查询全路径 / 控制面 CRUD + 越权）以及新增 capability 各自的关键 happy/sad path（anomaly / llm / rum / sso / federated / cipher / license / connector）。
