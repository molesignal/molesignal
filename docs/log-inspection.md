# 日志智能巡检

智能巡检让 Mole Agent 读一段时间的日志，写出一份报告：这段时间有没有问题、问题是什么、
依据是哪些日志。有两种用法：

- **按需巡检**：在「日志」页的「智能巡检」页签里，对当前查询立即巡检一次，报告在页面上
  流式写出。这次巡检是一条 Mole Agent 对话，可以到 Mole Agent 里继续追问；它不进入定时
  巡检的历史报告。
- **定时巡检**：把数据流、查询条件和巡检要求保存下来，后台按周期巡检，保存每次的报告，
  报告判定有异常时发通知。本文主要说明定时巡检。

两种用法都只读日志，不会修改任何数据或配置。

## 前提

- 组织里至少启用一个 AI 模型（「Mole Agent → 设置 → 模型与推理」）。没有启用的模型时，
  页签和定时巡检页面会说明原因，已保存的巡检仍然列出，但无法执行。
- 权限：

| 要做的事 | 需要的权限 |
| --- | --- |
| 按需巡检；查看定时巡检和历史报告 | `agent.use` 和 `streams.query` |
| 新建、编辑、启停、删除、立即执行一次 | `inspections.manage`（默认授予 owner、admin、editor） |
| 在表单里选择通知渠道 | `alerts.read`（用于列出通知连接器） |

缺少查看权限时，「智能巡检」页签会说明缺的是哪项权限，也不会出现通往定时巡检页面的
入口。

## 保存一条定时巡检

入口有两处：

- 「日志」页 →「智能巡检」页签 →「保存为定时巡检」：表单里已经带上当前的数据流、查询
  条件、巡检要求和所选模型。当前查询没有结果时也可以保存。
- 「日志」页 →「智能巡检」页签 →「定时巡检」，进入 `/logs/inspections` 后点「新建巡检」。

| 字段 | 说明 |
| --- | --- |
| 名称 | 组织内唯一，最多 120 个字符 |
| 数据流 | 一条日志数据流；巡检只能读这一条流 |
| 查询 | 选填。只巡检符合这个条件的日志，写法与「日志」页的查询相同；留空则巡检整条流 |
| 巡检要求 | 选填，最多 2000 个字符。告诉模型关注什么、什么算正常 |
| 周期 | 每隔一段时间，或每天 / 每周的某个时刻。两次执行的最短间隔由实例配置决定，默认 1 小时，表单只给出实例允许的间隔 |
| 覆盖时间 | 每次执行查看执行时刻之前多长时间的日志；表单里可选 15 分钟到 7 天（接口允许 5 分钟到 7 天），默认与周期一致 |
| AI 模型 | 组织里已启用的一个模型配置；保存时模型必须可用（存在、已启用、有密钥） |
| 何时通知 | 仅异常（默认）、需关注及以上、每次 |
| 通知渠道 | 选填，最多 10 个。每个渠道是一个通知连接器上的固定群组或固定地址 |
| 保存后按周期自动执行 | 关掉时只保存、不调度，仍可手动执行 |

每天 / 每周的时刻按新建时界面使用的时区计算（个人偏好里的时区，没有设置时是浏览器的
时区），表单里会写明是哪个时区，之后编辑不会改变它；夏令时切换时按当地时间执行。通知和
报告使用新建时界面的语言（中文或英文）。每个组织最多保存 20 条定时巡检（实例配置可调）。

## 执行

- **以谁的身份**：以最后一次保存这条巡检的人的身份执行，表单的保存按钮旁会写明。每次
  执行前都会重新核对这个人仍可登录、仍在组织内、仍有 `agent.use` 和 `streams.query`；
  核对不过时这次执行记为失败（原因「执行身份已不可用」），由其他有权限的人重新保存一次
  即可改用自己的身份。巡检读日志走的是与 Mole Agent 相同的工具通道，用的就是这个身份：
  这个人自己在 Mole Agent 里查不到的，巡检也查不到。API Token 不能保存定时巡检。
- **能做什么**：模型只能使用三个只读工具——`query_logs`、`get_stream_schema`、
  `search_field_values`，并且只能读巡检所选的那条数据流。组织的 Tool Policy 把其中某个
  工具设为需要审批或停用时，巡检不会使用它（后台没有人审批）。巡检不能发起任何变更。
- **时间窗口**：每次执行查看「执行时刻之前、覆盖时间那么长」的日志。节点停机期间错过的
  周期不会补跑；恢复后到期的巡检执行一次，下一次按周期顺延。
- **上限**：单次执行的总时长默认不超过 5 分钟，超过记为「超时」；最多 8 轮工具调用后必须
  给出报告；单个工具结果超过 64 KiB 时不交给模型，而是让它收窄查询（先计数、分组，少选
  字段）。执行失败不重试，等下一个周期。
- **并发**：同一条巡检同一时刻只有一次执行在进行；一个节点同时最多执行 2 条巡检。
- **立即执行一次**：在列表或详情页点「立即执行」，这次执行先排队，由执行巡检的节点在
  15 秒内取走，身份仍是巡检的执行身份，记录里会写明是谁点的。已停用的巡检也可以这样
  执行。

## 报告与结论等级

每次执行都会留下一条记录，在 `/logs/inspections/:id` 查看：左边是历次执行，右边是选中
那一次的报告、覆盖的时间范围、用时、调用过的工具、消耗的 token 和发出的通知。通知里的
链接带着 `?run=<执行 id>`，打开就是那一次的报告。

定时巡检的报告带一个结论等级：

| 等级 | 含义 |
| --- | --- |
| 正常 `normal` | 没有发现需要处理的问题 |
| 需关注 `attention` | 有值得留意的迹象，暂不构成故障 |
| 异常 `abnormal` | 发现了需要处理的问题 |
| 未判定 `unknown` | 模型的回答里没有可读的等级。报告原文照常保存，通知时按异常处理 |

执行没有完成时没有报告，记录里是状态和原因：

| 状态 | 原因 |
| --- | --- |
| 超时 `timed_out` | 超过了单次执行的时间上限 |
| 失败 `failed` | 执行身份已不可用；所选 AI 模型不存在、已停用或没有密钥；模型调用失败；执行节点中途退出；一直没有节点来执行；内部原因 |

报告保留 30 天（实例配置可调），过期的每小时清理一次；删除一条巡检时，它的全部报告一并
删除。

## 通知

- 报告的结论等级达到「何时通知」的要求时，向每个渠道各发一条：标题说明等级和巡检名称，
  正文是数据流、时间范围、等级、报告摘要和报告链接。实例没有配置 `http.external_url` 时
  正文里没有链接。
- 执行失败时，只要上一次执行不是失败就通知一次；连续失败只通知第一次，不受「何时通知」
  影响。
- 没有选渠道时不发通知，报告仍然保存。
- 每次发送都记在「通知 → 投递记录」里，来源显示为「直接发送」（`direct`）；这类投递不经过
  通知策略，不能从投递记录里重试。连接器已停用或目标不被接受时，这一条记为未送达并写明
  原因，不影响报告。
- 通知连接器被定时巡检引用时不能删除。

## 实例配置

```toml
[log_inspection]
# 同一条巡检两次执行之间的最短间隔，单位秒；小于 60 时按 60 处理。
min_interval_secs = 3600
# 每个组织最多保存多少条定时巡检；0 表示不允许创建。
max_per_org = 20
# 单节点同时执行的巡检数；0 按 1 处理。
concurrent_runs = 2
# 单次巡检的总超时，单位秒；小于 30 按 30 处理，大于 480 时收敛为 480。
run_timeout_secs = 300
# 巡检报告的保留天数；0 按 1 处理。
report_retention_days = 30
```

定时巡检由 `alert` 角色的节点执行，每 15 秒检查一次有没有到期或排队的巡检。部署多个
`alert` 节点时，每条巡检的每次执行只会被一个节点领走。节点中途退出留下的执行，在超过
时间上限两分钟后被记为失败（原因「执行节点中途退出」）；排队超过 15 分钟仍没有节点来取的
手动执行同样记为失败。

## 观测

| 指标 | 含义 |
| --- | --- |
| `log_inspection_runs_total{outcome}` | 结束的执行次数，`outcome` 为结束时的状态：`succeeded`、`failed`、`timed_out` |
| `log_inspection_run_duration_seconds` | 单次执行的耗时 |

模型调用的用量与 Mole Agent 的其他调用一样写入 `_agent_model_traces`，`source` 为
`log_inspection`。

## API

接口在 `/api/v1/logs/inspections` 下，字段见 [openapi.yaml](api/openapi.yaml)：

| 方法与路径 | 用途 |
| --- | --- |
| `GET /logs/inspections` | 列出组织的定时巡检 |
| `POST /logs/inspections` | 新建 |
| `GET /logs/inspections/limits` | 实例对定时巡检的限制 |
| `GET` / `PUT` / `DELETE /logs/inspections/{id}` | 读取、整体更新、删除（连同报告） |
| `POST /logs/inspections/{id}/enabled` | 启用或停用 |
| `POST /logs/inspections/{id}/run` | 立即执行一次 |
| `GET /logs/inspections/{id}/runs` | 历次执行，新的在前，不含报告正文；`limit` 默认 50、最多 200，`before` 取更早的 |
| `GET /logs/inspections/{id}/runs/{run_id}` | 一次执行，含报告正文 |
