# 01_cover

MoleSignal 是开源、可完全自托管的可观测性与事件响应平台，目标是把调查上下文、团队响应和模型控制留在同一环境中。本轮拟融资75万美元，计划覆盖24个月，重点从独立产品交付走向早期客户验证。目前产品处于发布前打磨阶段，尚无外部用户和付费客户，公司尚未注册。融资额、周期与阶段由创始人zek.carter提供。

---

# 02_pain

我们聚焦三类可能同时出现的困难：工具间上下文分散、总成本和维护人力难以管理、数据及AI权限需要可控。日志、指标、链路和事件切换会产生调查与交接负担；SaaS多维计费与自建组件维护对应不同的成本结构。这些是目标客户假设，而不是已有访谈结论，也不意味着每家竞品都存在这些问题。下一步需要从具体团队的现有工作流验证痛点频率和付费意愿。

---

# 03_solution

当前源码和文档覆盖统一遥测、事件响应、Mole Agent 与自主部署。日志、指标和链路可以通过SQL、PromQL与跨信号上下文进行调查；告警进入值班、升级、状态更新和复盘。Mole Agent在平台权限内使用工具，模型由组织选择，高风险操作经过审批。部署以Rust二进制、PostgreSQL元数据及本地或对象存储为基础。可以先接现有告警，再迁移遥测；这些实现尚未得到外部客户生产验证。依据：项目README.zh-CN.md及相关路由实现，2026-11-02读取。

# 06_response

事件响应包括告警接收、分组、路由、值班通知、升级、状态更新与复盘改进。Mole Agent用于记录假设与证据，辅助调查而不是保证根因结论正确。模型可以选择内网端点，工具执行复用身份与权限，高风险动作必须经过审批。减少交接是价值主张，可靠性、实际时间节省和调查质量仍需在试点中验证。依据：当前README中的告警与事件响应、Mole Agent章节。

# 07_customer

直接使用者是SRE、平台工程师、后端开发与值班人员；潜在预算决策者是CTO、工程负责人和平台负责人。初始假设是已有监控、业务需要值班但专职平台人力有限的SaaS或互联网服务团队。付费理由应来自托管运维能力与时间节省，而不只是功能数量。拟通过开源试用、创始人直访和设计伙伴发现需求，先验证告警响应，再考虑更广泛遥测迁移。当前画像、渠道与伙伴获取都未获得市场验证。

# 08_competition

竞争对手已覆盖广泛能力。Datadog提供可观测、事件响应、状态更新、复盘和Bits调查，并有按主机、摄入量、索引等不同计费维度。Grafana拥有Loki、Mimir、Tempo等项目生态，Cloud IRM提供值班与AI调查。OpenObserve支持统一遥测、单二进制自部署和Cloud，也包含Incidents、Workflows、AI SRE等；其开源核心为AGPL，Cloud主要按摄入GB收费。选择条件是我们对公开信息的判断，未运行竞品实测。MoleSignal不能把AI、Rust、对象存储或单二进制视为独有壁垒。官方来源，核实于2026-11-02：https://www.datadoghq.com/product/incident-response/ ；https://www.datadoghq.com/product/ai/bits-investigation/ ；https://www.datadoghq.com/pricing/ ；https://grafana.com/oss/ ；https://grafana.com/products/cloud/irm/ ；https://openobserve.ai/platform/ ；https://openobserve.ai/pricing/ 。

# 09_difference

选择MoleSignal的假设条件是：团队同时重视Apache 2.0开源、自主部署、模型选择、统一响应流程和渐进接入。我们希望通过一套体验降低拼装与交接负担，但这不是已经证明的优势。需要用安装成功率、持续使用、响应效率、客户留存和同等负载的总成本来检验。对OpenObserve尤其需要靠具体工作流体验取胜；对成熟SaaS或Grafana生态已有深度投入的团队，迁移收益必须明确。依据：MoleSignal LICENSE、README及前页官方竞品来源。
