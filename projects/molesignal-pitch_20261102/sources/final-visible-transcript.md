# 02_pain

01 / 客户痛点
工具很多，排障与运维仍然费力
上下文分散
日志、指标、链路和事件散落在不同工作流中，工程师反复对齐时间、服务、责任人与处理进度。
代价：调查与交接时间
总成本难管理
SaaS 账单随多种用量增长；自建又需要维护多个组件。软件、存储与工程师时间都进入真实成本。
代价：预算与平台人力
控制要求增加
日志可能包含敏感数据；AI 调查又引入模型访问、工具权限与操作审批，必须纳入同一治理边界。
代价：治理与部署复杂度
切入假设：团队需要把信号、响应流程和控制权收拢到一个产品。
目标客户痛点假设，尚待访谈与试点验证；不代表所有竞品或所有团队。

# 06_response

02 / 事件响应与 MOLE AGENT
把调查结果带进团队响应流程
面向值班团队
接收、分组并路由告警，通知值班人员。通过排班与升级策略明确响应责任。在事件中记录进展并更新状态页。把复盘改进项带入后续工作。
面向可控的 AI 调查
记录假设与证据，辅助根因调查。复用平台身份、权限与审计边界。模型由团队选择，可接内网模型。高风险操作审批后执行。
价值主张：减少工具间交接；可靠性与实际排障效果仍需试点验证。
当前实现与文档能力；不承诺自动根因结论或无人审批的生产修复。

Loki / Mimir / Tempo 生态，Cloud IRM 与 AI 调查。支持组件化选择与托管。

官方能力说明核实于 2026-11-02；适配人群为判断，非竞品实测结论。来源见备注。

# 09_difference

04 / 差异化与选择条件
为重视控制权与响应流程的团队而做
开放与控制
Apache 2.0；数据与模型可留在自有环境。适合将自主部署作为核心要求的团队。
观测与响应一起交付
统一调查、值班、状态页与审批体验。争取降低组件拼装与流程交接负担。
渐进采用
接收已有监控告警，兼容标准采集协议。从一个响应场景开始验证，不要求全迁。
需要证明的优势
部署成功率、响应效率、留存与总成本。目前没有客户证据或量化性能优势。
差异来自面向目标团队的组合与执行；未来壁垒需在真实使用中形成。
